# PHOSPHOR — Code Review & Security Audit

**Date:** 2026-08-15
**Scope:** Full repository (`johnnyclem/hypervault-phosphor`)

## Summary

PHOSPHOR is a client-side Web Audio synth keyboard + canvas video-synth,
built on TanStack Start (React 19) and deployed to Vercel as a static/SSR
site. The actual product surface — `src/lib/synth/*`, `src/components/synth/*`,
`src/components/hardware/*`, and the two routes (`/`, `/hardware`) — is
clean, has no server-side data access, and passed `tsc --noEmit` / `eslint`
with zero issues before any changes were made.

The rest of the repository was unused "app-builder" platform scaffolding:
a fully-wired Better Auth + Postgres/PGLite backend and a WebRTC multiplayer
client, neither of which was reachable from any route or imported by any
app component. That scaffolding has been removed (see "Changes applied"
below) after confirming with the repo owner.

## Findings

### Critical / High
None. No injection, auth-bypass, or data-exposure issues in the code that
actually serves traffic — the app has no backend and handles no user data.

### Medium
- **CI deploys straight to production with no test/lint gate.**
  `.github/workflows/deploy-vercel.yml` runs `npm install && npm run build`
  then deploys `--prod` on every push to `main`. `npm run build` does not
  run `lint` or `typecheck`. Recommend adding those as required steps before
  the deploy step (not changed in this pass — flagging for a follow-up since
  it touches the deploy pipeline).
- **No automated test suite.** `scripts/browser-smoke.mjs` and
  `scripts/synth-qa.mjs` are manual Playwright scripts, not wired into CI.
  Given the app is almost entirely interactive Web Audio/Canvas behavior,
  a lightweight CI smoke test (headless boot + click "Enable Audio" + assert
  no console errors) would catch real regressions cheaply.
- **No `.gitignore` existed.** Added one (`node_modules/`, `dist/`,
  `.output/`, `.vercel/`, `.nitro/`, logs) to prevent build artifacts or a
  future local `.env` from being committed accidentally.

### Low / Informational
- **Unused platform scaffold (now removed).** `src/lib/auth/*` (Better Auth,
  federated OAuth to an external "Grok auth broker"), `src/lib/db.ts` +
  `migrations/0001_auth.sql` (Neon/PGLite dual-backend DB layer), and
  `src/lib/multiplayer/*` (WebRTC mesh client expecting a `/api/rtc`
  signaling endpoint that never existed) were fully built but never mounted
  or imported by the app. The auth module was well-written — proper
  Fetch-Metadata sibling-site isolation, `__Host-`-prefixed cookies, secrets
  sourced from env with a documented low-privilege preview fallback — but
  none of it was reachable via HTTP (no `/api/auth/*` route file existed),
  so it added maintenance surface and eager PGLite boot/migration cost on
  every server start for zero product value. Removed by agreement with the
  repo owner; see "Changes applied."
- **~15 unused npm dependencies.** `recharts`, `zustand`, `zod`,
  `react-hook-form`, `@hookform/resolvers`, `cmdk`, `vaul`,
  `react-day-picker`, `@tanstack/react-table`, `@tanstack/react-query`,
  `date-fns`, `class-variance-authority`, `clsx`, `tailwind-merge`,
  `tw-animate-css`, `sonner`, `react-resizable-panels`, and all 18
  `@radix-ui/*` packages had zero imports anywhere in `src/`. Removed.
- **Dependency vulnerabilities (dev-tooling only).** `npm audit` reported 4
  advisories (3 high, 1 moderate): `brace-expansion` (via `eslint`/
  `typescript-eslint`), `js-yaml` (via TanStack Start's `xmlbuilder2`),
  `nanoid` and `postcss` (via `vite`). All were transitive build-time
  dependencies, never shipped to the browser bundle — low real-world risk,
  but fixed via `npm audit fix` (non-breaking patch bumps). `npm audit` now
  reports 0 vulnerabilities.
- **Hardcoded OAuth client secret** in the (now-removed) `preview.ts` —
  documented in-code as an intentionally shared, low-privilege,
  preview-sandbox-only broker client, not a real production secret. Moot
  after removal, noted for the record.

## Changes applied

1. Removed unused scaffolding: `src/lib/auth/**` (14 files), `src/lib/db.ts`,
   `src/lib/multiplayer/**` (2 files), `migrations/0001_auth.sql`,
   `scripts/migrate.mjs`.
2. Removed the corresponding Vite dev-server plugins (`pgliteBootstrapPlugin`,
   `authPopupPlugin`) from `vite.config.ts` and the `db:migrate` build step
   from `package.json`.
3. Removed ~15 unused npm dependencies (auth/DB stack + unused UI-kit
   packages) and their `@types/pg` dev dependency; kept `@tanstack/router-plugin`
   and other build-tooling packages that `vite.config.ts` still uses.
4. Ran `npm audit fix` — 4 transitive dev-tooling vulnerabilities (3 high, 1
   moderate) resolved, 0 remaining.
5. Added `.gitignore`.
6. Verified: `tsc --noEmit` clean, `eslint .` clean (0 errors/warnings — this
   also removed the one pre-existing stale `eslint-disable` warning, which
   lived in the deleted auth code), `npm run build` succeeds end-to-end
   (client + SSR + Vercel nitro output), and a headless-browser smoke pass
   confirms both routes (`/`, `/hardware`) load, the synth boots audio,
   keyboard input plays notes, and the video synth renders with zero
   console/page errors.
7. Installed package count dropped from 432 to 278.

## Not changed (flagged for follow-up, not done in this pass)

- Adding `lint`/`typecheck` as required CI steps before `deploy-vercel.yml`
  runs `--prod` deploy.
- Wiring a minimal automated smoke test into CI (the manual Playwright
  scripts already exist and could be adapted).

These are process/pipeline changes rather than application code, so they're
left for an explicit follow-up request rather than bundled into this cleanup.
